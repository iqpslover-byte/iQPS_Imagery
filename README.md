# iQPS_Imagery

iQPS（株式会社QPS研究所）の小型SAR衛星 **QPS-SAR** が撮像した画像と、それを地図に重ねるための四隅の座標を置く。

[OP's LAB Maps](https://github.com/iqpslover-byte/OPs_LAB_Maps) が `raw.githubusercontent.com` 経由で `scenes.json` を読み、SAR IMAGERY メニューの「iQPS」から地図に重ねる。

**画像の著作権は iQPS に帰属する。** ここは地図に重ねて見るための置き場であり、権利を主張するものではない。

---

## scenes.json の形式

```json
{
  "scenes": [
    {
      "id": "kyoto",
      "file": "kyoto.jpg",
      "size": [4500, 3080],
      "corners": {
        "tl": [35.050074, 135.712931],
        "tr": [35.069699, 135.771825],
        "br": [35.017479, 135.800478],
        "bl": [34.997854, 135.741585]
      }
    }
  ]
}
```

| 項目 | 意味 |
|---|---|
| `id` | シーンの識別子 |
| `file` | このリポジトリ内の画像ファイル名 |
| `size` | 画像の画素数 `[幅, 高さ]` |
| `corners` | 四隅の `[緯度, 経度]`。**画像の画素の並び順**で `tl`=左上 `tr`=右上 `br`=右下 `bl`=左下 |

画像を足すときは、ファイルを置いて `scenes` に1件加えるだけでよい。アプリ側の改修は要らない。

---

## 四隅の座標について

SAR画像は斜めから撮像するため、**北が上を向いておらず、方向によって縮尺も違う**。単純な回転や矩形では地図に重ならず、四隅を指定するアフィン変換が要る。

`corners` は必ず**平行四辺形**になる（アフィン変換の像なので、対辺は平行）。地図側はこの4点だけで正しく貼れる。

### kyoto

京都市街。賀茂川と高野川の合流点（出町柳）を含む。

| | |
|---|---|
| 画像 | 4500 × 3080（元は 6000 × 4107） |
| 地上分解能 | 東西 1.37 m/px ／ 南北 1.82 m/px |
| 北の向き | 画像の真上から**東へ 35.4°** |
| 画像上の東西軸と南北軸の交角 | **68.9°**（地上では直交） |
| 範囲 | およそ 8 km 四方・34.4 km² |

四隅は画像から実測した。**京都御所の築地塀**（実寸 453.2 m × 254.6 m）の四隅を読んでアフィン変換を組み、**京都御苑・二条城・下鴨神社の糺の森**の3つで重なりを確認している（基準から 2.5 km 離れた二条城でも合う）。

京都の街路は直交しているが、この画像上では 69° に潰れて写る。その角度をフーリエ変換で独立に測ったところ 69.0° で、アフィン変換から出た 68.91° と一致した。

撮像幾何もここから逆算できる。画像の右方向は地上で方位 67.9°、下方向は方位 155.8°（両者は地上で 87.9°＝ほぼ直交）。アジマス方向の方位 67.9° は、軌道傾斜角 42° の衛星が緯度 35.0° を北上するときの地上軌跡の方位（理論値 65.2°）と近く、**昇交パスでの撮像**と整合する。スラントレンジ分解能をアジマスと同じと仮定すると入射角 38.8°＝**オフナディア角およそ 35°**。
